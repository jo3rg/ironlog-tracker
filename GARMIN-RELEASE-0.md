# Garmin release 0: deploy a workout to the watch

IRON.LOG exports a workout prescription as `.FIT` and imports the original `.FIT` file of a completed Garmin strength activity. The import is manual, offline, and idempotent for the same file.

The software side is covered automatically by `npm run test:e2e` (see `README.md`): the suite exports every plan day, validates the bytes with the Garmin FIT SDK, and imports simulated completed activities through the real UI. Everything below is what the automated suite cannot cover: the watch, Garmin Connect, and the original activity file from a real device.

## 1. Build the artifacts

```sh
npm install
npm run dist:all
```

Result:

- `dist/` – the deployable PWA (`index.html`, `garmin.js`, `manifest.json`, `sw.js`, icons). Upload this folder to any static HTTPS host.
- `dist/workouts/ironlog-ua.fit` (and `la`, `ub`, `lb`) – workout prescriptions for the default plan, generated by the same code path as the app download.

`npm run fit:export -- --day UA` regenerates a single day; `--plan hyrox-demo` switches the plan. WOD-format days (EMOM, AMRAP, For Time) are skipped because the exporter only supports strength days.

`npm run fit:export -- --no-rest` writes a second variant (`ironlog-ua-norest.fit`) without the explicit rest steps. Use it if the watch skips or misplaces the rest between sets. `--verbose` prints every step (name, duration, repetitions, exercise code) so the file can be compared with what the watch shows.

## 2. Put the workout on the watch

1. Open Garmin Connect web → **Training & Planning → Workouts** → **Import** and choose `dist/workouts/ironlog-ua.fit`.
2. Inspect the imported workout, then **Send to Device** and pick the watch.
3. On the watch: open the workout under Strength workouts. It must open without an error.

## 3. Check the workout on the watch

1. Exercise order and names must match the plan day. `Klimmzüge (oder Latzug breit)` and `Beinstrecker` have no Garmin catalog entry, so they are exported as custom labels and may show without muscle group or animation.
2. Every exercise must show the intended set count, rep target, and rest. The exporter reduces a rep range to its lower bound (`6-8` becomes `6`) and adds no target weight unless the app history already holds one for that exercise.
3. Run one representative set: rep counting, set completion, rest timer, and the transition to the next exercise must behave as expected.
4. Stop and save the workout. It must appear in Garmin Connect as a completed activity. This file is a **workout prescription**, not a completed activity; it must never be uploaded as an activity.

## 4. Record the activity and get it back into the app

1. Sync the watch with Garmin Connect, open the saved strength activity and choose **Export Original** to download its original `.FIT` file (usually into the browser's download folder).
2. Open IRON.LOG → **Stats → Daten → Garmin-Aktivität importieren (.FIT)** and choose that file.
3. Check **Stats**: the calendar marks the day, the volume chart shows the sets, and the personal bests list the heaviest set. The importer keeps active sets with reps and weight, duration-only sets as seconds, plus session duration, calories, and heart-rate summary. Importing the same file again is skipped.

## If something fails

| Symptom | Cause | Next step |
| --- | --- | --- |
| Garmin Connect refuses the file | Not a FIT workout | Use the file from `dist/workouts/`, not a course or activity export |
| Watch shows an unnamed exercise | No Garmin catalog entry | Expected for custom labels; rename on the watch if needed |
| Watch skips the rest between sets | Step layout of the repeat block | Test the second file: `npm run fit:export -- --no-rest` and send that one |
| Import says "keine Garmin-Krafttrainingsaktivität" | Wrong file type | Export the **original** FIT of the activity, not TCX, GPX, or a course |
| Import says "bereits importiert" | Same file imported before | Expected; delete the entry in the history to re-import |
| Activity lands on the wrong day | Local time in the file | The importer prefers the UTC start time; report the file if the date is still wrong |

## Known limits

- `garmin.js` generates a `.FIT` workout locally. It does not call Garmin APIs or connect to the watch.
- Transfer is manual through Garmin Connect or a compatible USB workflow.
- The app exports the selected day from the active plan, not a completed workout from history.
- Exercise catalog mappings cover common names only. Unmapped names use Garmin's `unknown` category plus a custom exercise title; watch rendering varies by model.
- Repetition ranges are reduced to their lower bound. Weight is inferred from the latest saved set for the same exercise ID/name; confirm it is sensible before sending.
- The activity importer accepts strength activities that contain FIT set records. It imports active sets only; Garmin exercises without a workout-step/title mapping use a category-based or generic label.
- Import is manual; there is no Garmin account connection, automatic result sync, or live phone control. Watch hardware behavior remains unverified until tested on a real device.
